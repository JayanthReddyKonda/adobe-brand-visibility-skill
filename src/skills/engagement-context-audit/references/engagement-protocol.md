# Engagement evidence, counterexamples and remedy tests

Use desktop 1365x768 and mobile 390x844, locale en-US and UTC; record deviations. Capture initial and bounded settled state in fresh unauthenticated contexts. Never infer universal visitor behavior from these states. Each candidate requires URL, viewport, state, exact text, coordinates and screenshot where visual evidence is material. Distinguish source, visible DOM, accessible naming, offscreen, clipped and covered content.

| Check | Minimum evidence / counterexample | Recommendation and acceptance |
| --- | --- | --- |
| I1 | Observed content unit at a genuine URL; repeat fresh entry and reload, matching identity. Working fragment anchors and query product URLs are legitimate. Status alone is insufficient. | Preserve route identity and legacy links; test clean entry, reload, sharing, source and rendered identity in a representative environment. C; S3 only on a demonstrated lost content unit, S4 only established access blocker. |
| I2 | Safe baseline/probe/baseline plus repeated regression with same entity and controlled variation. Ignore benign stripping redirects. Unknown experiments or meaningful/signed query parameters block probing. | Handle only the demonstrated inert parameter without stripping meaningful queries; repeat controls. C; S2 local loss, S3 material essential fact failure; otherwise U. |
| J1 | Quote actual identity statement with viewport coordinates. Missing H1 and generic greeting alone are not failures. | Optional rewrite using existing name, audience and offering; preserve facts, inspect both layouts, recommend comprehension research. E; S1 advice. |
| J2 | Visible navigation link and repeat destination failure; source-only links cannot prove visibility. Alternative navigation and single-page sites are valid. | Repair to a verified equivalent or restore intended destination; test keyboard, mobile and return route. C; S2 local broken path, S3 only material navigation blocker. |
| J3 | Owner-established important fact, exact bounding box, viewport intersection, clipping and hit test. Below-fold placement is not necessarily bad. | Optional placement revision; test factual parity and accessible presentation across viewports. E; S1 advice, no invented conversion impact. |
| J4 | Observed safe CTA path and explicit blocking state. Do not submit forms or infer total checkout steps from controls. Required login/consent may be legitimate. | Conditional workflow proposal only with task requirements; test an owner-supplied staging flow, never a transaction in this audit. C; severity only supported observed blockage. |
| J5 | Actual review/credential/case-study text and cited source. Presence does not establish authenticity; absence does not establish distrust. | Present genuine supplied proof appropriate to the page, with permission and context. C; optional S1 unless a separate factual contradiction is demonstrated. |
| J6 | Essential content named; screenshot and hit-test show it physically covered in repeated comparable states, with dismissal affordance recorded. z-index, fixed position and dialog role alone do not establish obstruction. C; S2 local obstruction, S3 substantial task obstruction, S4 only a demonstrated essential access blocker. |
| J7 | Actual post-completion state is outside URL-only read-only scope. A mock confirmation page is not a completed flow. | X/U; log not_possible. Do not invent a follow-up experience or exercise the flow. |
| J8 | Naturally encountered explicit unavailable state and visible safe alternatives, with destinations checked. Do not force stock changes or assume relevance from similar names. | Use verified category/support routes or genuinely available compatible inventory. C; S2 only demonstrated recovery gap under known intent; otherwise inventory/advice. |
| J9 | Naturally encountered HTTP 404, actual error text and observed recovery links. A source inventory is not proof of visible absence. Soft 404 requires content review, not status alone. | Generate a narrow 404 body only from verified usable links. Parse markup and test keyboard/mobile; server integration must preserve 404. V/S2 when recovery failure is established; otherwise observation. |
| J10 | Duplicate of H1 timing and H3 viewport parity. Timing has no automatic defect without an established budget. | X/S0; link to the single supported H1/H3 task. |

No new engagement checks were added: the existing bridge/engagement items cover observable continuity and recovery; personalization, email summaries and completed-flow outcomes need unavailable input. This avoids claiming novel coverage without evidence.
